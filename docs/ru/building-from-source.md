# Сборка из исходников

[← Оглавление документации](../README.md)

Для разработчиков, кто хочет запускать приложение из клона. **Только Windows.**

## Требования

- **Python 3.12+** в `PATH`.
- **Установленный Team Fortress 2**, нужен для сборки модов, и `vpk.exe` берётся из
  `<TF2>\bin\`.

## Сторонние тулзы

Crowbar и VTF-тулзы (`VTFCmd.exe`, `VTFLib.dll`, `HLLib.dll`, `DevIL.dll`) уже **закоммичены в
`tools/`**, качать для них ничего не нужно. Их лицензии (CC BY-SA 3.0 / LGPL / GPL) разрешают
редистрибуцию; см. [`THIRD_PARTY_LICENSES.md`](../../THIRD_PARTY_LICENSES.md).

Единственная тулза, которой **нет** в репо, это **`vpk.exe`**: проприетарный бинарь Valve.
Приложение берёт его из установленной TF2 (`<TF2>\bin\vpk.exe`) автоматически; можно также
положить копию в `tools/VPK/` как запасной вариант, если не хочется зависеть от установки TF2.

## Настройка и запуск

```bat
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python main.py
```

`requirements.txt` содержит рантайм-зависимости: PySide6 (Essentials + Addons), Pillow, `vpk`,
`srctools`, NumPy. `requirements-dev.txt` добавляет сверху dev/тест-оснастку (PyInstaller,
coverage, vulture, ruff).

## Структура проекта

```
main.py                 точка входа (логи, сплэш, запуск MainWindow)
src/
  ui/                   виджеты PySide6: главное окно, панели, диалоги, превью
  services/             конвейер сборки: VTF/VMT/VPK, декомпиляция/компиляция модели, диагностика
  data/                 статические таблицы (оружие, шапки, персонажи, небо…)
  config/, shared/      конфиг, логирование, версия, константы
tools/
  crowbar/, VTF/        декомпилятор Crowbar + VTF-тулзы (в репозитории)
  VPK/                  опциональный запасной vpk.exe (иначе берётся из TF2)
  Model/                пустые заглушки по классам (.gitkeep)
requirements*.txt       рантайм- и dev-зависимости
```

Версия лежит в `src/shared/version.py`, это единственный источник правды: её использует апдейтер
в UI и билд-скрипт при штамповке инсталлятора.

## Релизные сборки

Релиз — два файла из одной сборки: `Tf2SkinGenerator-Setup.exe` (установщик Inno Setup с
приложением внутри) и `Tf2SkinGenerator-portable.zip` (та же папка, распаковал и запустил).
Оба собирает `build-release.ps1` (в репозитории); скрипт установщика
`installer/Tf2SkinGenerator-bundle.iss` гитигнорится. Нужны `.venv` и
[Inno Setup 6](https://jrsoftware.org/isdl.php).

```bat
release.bat -Version 1.0.4
```

Скрипт поднимает версию в `src/shared/version.py`, собирает приложение PyInstaller по спеке
(`--onedir --windowed`), копирует `tools/` в корень сборки, пакует всё в установщик и следом в
zip — оба в `installer\Output\`. `-SkipDeps` пропускает переустановку пакетов.

Дальше руками:

1. Запустить полученный `Setup.exe` у себя и убедиться, что приложение ставится и открывается.
2. Закоммитить поднятую версию.
3. Создать релиз на GitHub с тегом `v1.0.4` — обычный, **не черновик и не пре-релиз**: их
   проверка обновлений пропускает.
4. Приложить оба файла, не переименовывая. Установщик обязателен, zip — для тех, кто не хочет
   ставить.

Обновление из приложения работает по этим правилам: оно спрашивает у GitHub последний релиз,
сравнивает версию тега со своей, находит в релизе установщик по имени
(`ASSET_NAME` в `src/services/update_checker.py`), сверяет SHA-256, который GitHub считает сам,
и запускает его тихо. Текст релиза показывается в приложении как заметки к версии.

Портативная копия обновляется тем же установщиком: файл-маркер `PORTABLE` в её папке (кладёт
скрипт в zip) переключает апдейтер на запуск `Setup.exe /PORTABLE=1 /DIR="<эта папка>"`, и тот
подменяет файлы на месте, не оставляя ни ярлыков, ни деинсталлятора, ни записи в «Программах и
компонентах». Папка должна быть доступна на запись без прав администратора.

## Заметки

- Логи пишутся в `tf2sg.log` рядом с приложением (в корне репозитория при запуске из исходников).
- Конфиг лежит в `config/app_config.json`, создаётся с дефолтами при первом запуске. Он
  гитигнорится целиком: в репозитории в `config/` на самом деле ничего не закоммичено, так что
  наследовать из клона нечего, локальный конфиг всегда стартует с чистого листа.
- Лицензии сторонних тулз: см. [`THIRD_PARTY_LICENSES.md`](../../THIRD_PARTY_LICENSES.md).
