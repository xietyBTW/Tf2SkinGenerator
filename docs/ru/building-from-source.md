# Сборка из исходников

[Документация](../README.md) · [English version](../en/building-from-source.md)

Эта страница для тех, кто хочет запустить приложение из репозитория, что-то в нём поменять или собрать релиз. Приложение работает только под Windows: оно опирается на виндовые инструменты игры, WebView2 и библиотеки, которые есть только под Windows.

## Что понадобится

| Инструмент | Зачем |
|---|---|
| Windows 10 или 11, 64 бита | Приложение и инструменты в комплекте собраны под Windows. |
| Python 3.12 или новее | Само приложение. CI работает на 3.12. |
| Team Fortress 2 | Приложение читает её архивы и вызывает `studiomdl.exe` и `vpk.exe` из `<TF2>\bin`. Без игры можно гонять тесты, но не настоящую работу приложения. |
| Microsoft Edge WebView2 Runtime | Окно, в котором показывается интерфейс. |
| Node.js (по желанию) | Проверка типов в JavaScript-модулях страницы. |
| Inno Setup 6 (только для релиза) | Сборка установщика. |
| Visual Studio 2022 Build Tools (редко) | Только чтобы пересобрать `meshoptimizer.dll`. |

## Настройка окружения

```bat
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python main.py
```

В `requirements.txt` то, что нужно приложению для работы: pywebview, Pillow, vpk, srctools и NumPy. `requirements-dev.txt` добавляет к ним инструменты разработки: PyInstaller, coverage, vulture и ruff.

Два пакета необязательны:

- `vtf2img` переводит извлечённые текстуры в PNG, TGA или JPG (**Настройки → Формат извлечения**). Без него извлечение оставляет VTF и пишет об этом в журнал.
- `pytest` гоняет тесты с фикстурами из `tests/conftest.py`, которые уводят временные файлы и черновики в одноразовую папку.

### Инструменты в комплекте

Они лежат в `tools/` и закоммичены в репозиторий, так что качать ничего не нужно:

| Папка | Что там |
|---|---|
| `tools/crowbar/` | консольный декомпилятор Crowbar |
| `tools/VTF/` | VTFCmd с VTFLib, HLLib и DevIL |
| `tools/meshoptimizer/` | `meshoptimizer.dll` для упрощения импортированных моделей, собирается скриптом `scripts/build_meshoptimizer.ps1` |

`vpk.exe` и `studiomdl.exe` принадлежат Valve, и в репозитории их нет. Приложение берёт их из `<TF2>\bin`. Если не хочется зависеть от игры при упаковке, копия `vpk.exe` в `tools/VPK/` имеет приоритет.

Вспомогательные `.bat` и `.ps1` git игнорирует, кроме `build-release.ps1` и `scripts/build_meshoptimizer.ps1`. Если где-то упоминаются `run.bat` или `release.bat`, это локальные удобства, а не часть проекта.

## Запуск

| Команда | Что делает |
|---|---|
| `python main.py` | Приложение целиком: журнал, проверка единственного экземпляра, перенос данных, затем окно. |
| `python frontend/app.py` | Только окно и его локальный сервер, без остального `main.py`. Если pywebview не установлен, страница откроется в окне Edge или Chrome в режиме приложения или в браузере по умолчанию. |
| `python frontend/devserver.py 5174 --work-dir .devwork` | Сервер для разработки. Откройте в браузере `http://127.0.0.1:5174`. |

При запуске из исходников папкой данных служит сам репозиторий: `config/`, `work/`, `mods/`, `export/`, `cache/`, `tools/temp/`, `tools/edited_vmt/` и журналы появляются рядом с кодом. Все они перечислены в `.gitignore`.

### Сервер для разработки

Сервер для разработки отдаёт ту же страницу и то же API по HTTP, так что над интерфейсом можно работать в обычном браузере с его инструментами разработчика.

- Открывайте `127.0.0.1`, а не `localhost`. С `localhost` Chromium сначала пробует IPv6, получает отказ и откатывается назад, и каждый вызов API становится медленнее примерно на 300 мс.
- `--work-dir .devwork` уводит черновики и работы сервера из `work/`. Без этого сервер, запущенный рядом с открытым приложением, пишет в те же черновики, что и приложение. Файл настроек и правки VMT у них всё равно общие.
- Сервер отвечает только на методы API из списка `ALLOWED` в `frontend/devserver.py`. Новый метод в `src/app/api.py` нужно добавить и туда.

```
  devserver.py            HTTP-транспорт: статика, POST /api/<метод>, /upload, /events, /file
  mockup/                 страница: index.html, style.css и ES-модули, вход в app.js
  CONTROLS.md             какой контрол в каком режиме виден и почему
  check.mjs, tsconfig.json, package.json   проверка типов в модулях
src/
  app/                    прикладной слой: api.py (то, что зовёт страница), session.py (AppSession),
                          preview_controller.py, parts_editor.py, particles_editor.py
  domain/                 состояние без ввода-вывода: сеанс превью, состояние текстур, выбор форматов
  services/               сама работа: VTF, VMT, VPK, декомпиляция и компиляция, сборка,
                          диагностика, звуки, частицы, War Paint, импорт моделей
  data/                   таблицы и разбор данных игры: оружие, items_game, косметика, звуки,
                          источники частиц, переводы
  shared/                 пути, журнал, константы, проверки, классификатор ошибок, версия
  config/                 AppConfig: чтение и запись config/app_config.json
  static/                 3D-вьювер (viewer3d.html, three.js) и движок частиц (particles3d.html)
tools/                    сторонние инструменты в комплекте
tests/                    тесты
scripts/                  обслуживание: порог покрытия, проверка страницы, сборка таблиц данных, сборка meshoptimizer
Tf2SkinGenerator.spec     спека PyInstaller: единственный источник того, что попадает в сборку
build-release.ps1         скрипт выпуска релиза
```

## Как это устроено

**Окно.** Никакого GUI-тулкита нет. `frontend/app.py` поднимает небольшой HTTP-сервер на `127.0.0.1` на случайном свободном порту и открывает страницу в окне pywebview, которое под Windows работает на Edge WebView2. 3D-вьювер и движок частиц живут отдельными страницами из `src/static` и загружаются в iframe.

**Вызовы.** Страница общается с Python через один модуль, `frontend/mockup/api.js`. Каждый вызов уходит запросом `POST /api/<метод>` с параметрами в JSON; сервер передаёт его одноимённой функции в `src/app/api.py` и возвращает `{result}` или `{error}`. `api.py` ничего не знает об HTTP: его функции принимают и возвращают обычные значения, поэтому их можно проверять без браузера.

**События.** Долгие операции (загрузка модели, сборка, извлечение) идут в рабочих потоках из `src/services`. Сеанс (`src/app/session.py`) превращает их сигналы в события в очереди, а страница получает их как Server-Sent Events из `GET /events`, причём у каждого подписчика своя очередь. Разбирает их `frontend/mockup/events.js`. Файлы, которые делают воркеры, например сетки OBJ и PNG для превью, отдаёт `GET /file`, и только из временной папки и папок данных приложения.

**Правила живут в Python.** Какие контролы показывать в режиме, решает `controls_for(mode)` в `src/app/api.py`, а страница только применяет ответ. Почему правила именно такие, объясняет `frontend/CONTROLS.md`. Правила в одном месте не дают странице разойтись с тем, что на самом деле делает сборка.

**Слои.** `domain` ничего не импортирует из `app` и `services`, а `services` ничего не импортирует из `app`. За этим следит `tests/test_layer_boundaries.py`, разбирая импорты.

**Два корня на диске.** `src/shared/paths.py` разделяет `install_dir()`, файлы программы, доступные только для чтения, потому что обновление их заменяет, и `data_dir()`, куда пишется всё, что пишет приложение. В собранном приложении данные лежат в `%LOCALAPPDATA%\Tf2SkinGenerator`, а при запуске из исходников оба корня указывают на текущую папку. Новый код, который пишет файлы, обязан идти через `data_dir()`.

**Сборка мода.** Сборка скина разбирает предмет через Crowbar (результат кэшируется в `%USERPROFILE%\.tf2skingen_cache`), правит QC так, чтобы материалы смотрели в папку обхода sv_pure, переводит картинки в VTF через VTFCmd, пишет VMT, компилирует модель `studiomdl` и упаковывает папку через `vpk.exe`. `BuildRequest` описывает сборку, `BuildWorker` запускает её в потоке, а работу делает `VPKService`.

**Переводы.** Интерфейс написан по-русски, и русские строки служат ключами. Английский словарь лежит в `frontend/mockup/strings.js`. Строка с подстановкой пишется одним шаблоном с `{}` (`Собрано: {}`) и никогда не склеивается из кусков, иначе словарь её не найдёт. Названия предметов Python отдаёт уже на нужном языке. Сообщения Python лежат в `src/data/translations.py`, а `src/shared/error_classifier.py` превращает сырые ошибки в объяснения на языке интерфейса. Отладочные и информационные записи журнала намеренно остаются русскими: их читает разработчик.

Комментарии в коде тоже на русском.

## Тесты и проверки

| Команда | Что проверяет |
|---|---|
| `python -m ruff check src main.py tests` | Неопределённые имена, неиспользуемые импорты, переопределения (набор правил `F`, см. `ruff.toml`). |
| `python -m pytest tests -q` | Тесты, с фикстурами из `conftest.py`. |
| `coverage run -m unittest discover -s tests` | Те же тесты так, как их гоняет CI. |
| `python scripts/check_coverage.py coverage.json 40 28` | Порог покрытия: 40 % строк и 28 % ветвлений. Сначала выполните `coverage json -o coverage.json`. |
| `python -m vulture src main.py --min-confidence 80` | Мёртвый код. Для более глубокого просмотра локально понизьте порог до 60. |
| `python scripts/check_frontend.py` | Страницу саму с собой: каждый id, который ищет код, есть в `index.html`, каждый метод API экспортирован из `api.js`, разрешён сервером и определён в `api.py`, у каждого события из Python есть обработчик. |
| `npm install`, затем `npm run check` в `frontend/` | TypeScript проверяет JavaScript-модули на сломанные импорты и имена. Известный шум сужения DOM отфильтрован. |

GitHub Actions (`.github/workflows/ci.yml`) на каждый push и pull request гоняет ruff, тесты с покрытием и его порогом и vulture, под Windows с Python 3.12.

## Выпуск релиза

Релиз состоит из двух файлов одной сборки:

- `Tf2SkinGenerator-Setup.exe`: установщик Inno Setup с приложением внутри. Обновление из приложения ищет именно файл с таким именем.
- `Tf2SkinGenerator-portable.zip`: та же папка для тех, кто не хочет ставить, с файлом-маркером `PORTABLE` внутри.

Оба делает `build-release.ps1`:

```powershell
powershell -ExecutionPolicy Bypass -File build-release.ps1 -Version 1.0.7
```

Без `-Version` скрипт спросит версию (Enter оставит текущую), а `-SkipDeps` пропускает переустановку пакетов. Скрипт:

1. Записывает версию в `src/shared/version.py`, единственный источник версии для приложения, проверки обновлений и установщика.
2. Ставит зависимости и PyInstaller в `.venv` и проверяет, что pywebview импортируется.
3. Собирает приложение PyInstaller по `Tf2SkinGenerator.spec` (одна папка, без консоли) в `build\release\`.
4. Копирует `tools\` рядом с исполняемым файлом, пропуская рабочие папки и игровой контент, который нельзя распространять.
5. Останавливается, если в сборку попал чей-то личный `app_config.json`.
6. Собирает установщик через Inno Setup, затем zip, и печатает SHA-256 установщика.

Оба файла оказываются в `installer\Output\`.

> [!IMPORTANT]
> Скрипт Inno Setup (`installer\Tf2SkinGenerator-bundle.iss`) и иконка приложения (`installer\assets\icon.ico`) лежат в папке `installer/`, которая исключена из репозитория через `.gitignore`. В свежем клоне их нет, а нужны они и скрипту релиза, и спеке PyInstaller.

После скрипта:

1. Запустите новый `Setup.exe` у себя и убедитесь, что приложение ставится и запускается.
2. Закоммитьте смену версии.
3. Создайте на GitHub релиз с тегом `v1.0.7`. Он должен быть обычным: проверка обновлений пропускает черновики и пре-релизы.
4. Приложите оба файла, не меняя их имён.

### Как обновление из приложения использует релиз

Приложение спрашивает у GitHub API последний релиз и сравнивает его тег со своей версией. Оно находит файл `Tf2SkinGenerator-Setup.exe` (`ASSET_NAME` в `src/services/update_checker.py`), скачивает его, сверяет размер и SHA-256, которые GitHub считает для каждого файла, и запускает в тихом режиме. Установщик ждёт, пока приложение закроется (он знает его мьютекс), заменяет файлы и запускает новую версию.

Портативная копия обновляется тем же установщиком. Файл `PORTABLE` рядом с исполняемым файлом заставляет обновление запускать `Setup.exe /PORTABLE=1 /DIR="<эта папка>"`. Так файлы заменяются на месте, а ярлыки, деинсталлятор и запись в списке установленных программ не создаются. Папка должна быть доступна для записи без прав администратора.

Если приложение запущено из исходников, проверка обновлений предлагает только ссылку на страницу релиза.
